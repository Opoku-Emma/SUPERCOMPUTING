# Assignment

Biological data has grown exponentially large due to a steep decline in sequencing costs. However, this growth is disproportional to the current pace at which we analyze the data itself. The complexity of generated data, lack of adequate computing power, and sometimes algorithm inefficiency, are generally the key limitations. As a doctoral student, these limitations can pose a significant challenge to my research if a personal computer is the only means for processing the vast amount of data I generate and collect from external sources. With sufficiently advanced computing power, I believe these limitations can be circumvented. This has been my motivation for learning high-performance computing (HPC), where speed and computational power are non-trivial for timely analysis of my data.

Over the course of the semester, my ultimate goals are to become an adept user of large computing power for big biology data, proficient in bash programming, and skillful at translating real-world genomic datasets into reproducible, well-documented analysis pipelines. While I have some experience using HPC clusters, it has mostly been a matter of learning on the job; thus a formal training is lacking. By the end of the semester, I envision becoming adequately familiar with working through the terminal, programmatically writing scripts that do much of the work with minimal intervention, and even ready to write programs for public use.

My main approach to learning is repeatedly practicing what I am taught. Looking back on my academic journey, I've found that actively engaging with materials through iterative practice, particularly in coding classes, has proven especially useful. In light of this, I plan to read through the relevant course material while practicing side-by-side. A minimum of three hours per week reading and coding alongside our coursework will serve as a good supplement to whatever material we cover in class, thus improving my skills over time while building muscle memory with the use of conventional tools.

My folder structure is good enough for reproducible research because it groups project files based on their use case. The readings accompanying this assignment reinforced that it is always worthwhile to stay organized, especially when sharing code with others or building tools that other people will use.

Documenting code is useful for three purposes; revisiting code in the future, code sharing, and results validation by independent researchers. Writing code in the present mostly appears comprehensible until it is revisited after a while. Without any documentation it becomes challenging to understand what the code was intended to do or even to debug it. Moreso, code is usually not used by one person. Regularly, it has to either be deposited online for public use or shared with others to replicate whatever findings were initially observed. Whichever the case, it is helpful to have descriptive phrases or sentences that explicitly inform the reader about the original intent of the code. Referencing the reading material again, this reinforces the idea of writing code for humans and, tangential to this, writing data for computers.

I have mostly programmed in Python, R, and occasionally done some bash scripting until I started my masters. I didn't need to do some hardcore bash scripting or terminal use since most of the code I used were like templates that only needed changing a few parameters. For the most part, it was about debugging, setting up project structure, and writing simple scripts. I hope to become proficient in bash scripting which is fundamental to making data analysis pipelines for my research
